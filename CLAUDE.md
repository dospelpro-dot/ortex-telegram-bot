# Миссия проекта

**Главная цель Claude Code в этом репозитории:**

> Находить ранние **рефлексивные петли розничного внимания** в US-equities —
> до того, как их подхватят momentum-кванты и ETF-потоки.
> Выдавать **3 имени** с потенциалом **+15% за 1–3 дня**, приоритет — **social velocity**.

Всё, что ты здесь делаешь, служит этой цели. Когда решение неоднозначно —
выбирай вариант, который повышает точность и своевременность сигнала.

---

## Тезис (почему это работает)

Розничное внимание **рефлексивно**: упоминания → покупатели → рост цены →
ещё больше упоминаний. Мы ловим фазу **ускорения** этой петли, а не пик.

- **Раньше momentum-квантов** — кванты входят по *реализованному* импульсу.
  Значит, имя должно быть ещё НЕ разогнанным (умеренный prior-move, RSI не
  перекуплен, объём только начинает расти). Уже улетевшее имя = поздно.
- **Раньше ETF-потоков** — ETF/индексы дают механический бид по AUM/включению.
  Значит, приоритет мелким, слабо-институциональным, не-индексным именам.
- **Squeeze как усилитель** — высокий short interest + растущий cost-to-borrow +
  опционная гамма делают петлю самоусиливающейся (шортокрыл).

## Как устроен пайплайн

```
universe.py      → кандидаты (StockTwits trending + watchlist.txt)
sources/         → адаптеры данных (каждый деградирует мягко при отсутствии ключа)
  market.py      → цена, prior-move, rVol, RSI, ликвидность, cap (Polygon → yfinance)
  ortex.py       → SI %float, CTB, utilization, DTC, опционы (топливо сквиза)
  social.py      → velocity/acceleration упоминаний (StockTwits/X/Reddit) ← ГЛАВНОЕ
scoring.py       → фильтры-гейты + 4 суб-скора → композит
pipeline.py      → run_scan() → топ-N → format_report() (Telegram HTML)
bot.py           → /scan /status /start + опц. авто-скан
config.py        → все веса/пороги/ключи (правь тут, не в логике)
```

## Веса скоринга (по умолчанию)

| Компонент        | Вес  | Что ловит                                   |
|------------------|------|---------------------------------------------|
| social_velocity  | 0.40 | ускорение внимания от низкой базы (главное) |
| squeeze_fuel     | 0.30 | short interest / CTB / DTC (усилитель)      |
| early_stage      | 0.20 | тайминг: до импульса, не на пике            |
| retail_owned     | 0.10 | мелкий/не-институциональный (до ETF)        |

Меняй веса и пороги через `.env` (`W_SOCIAL`, `FILTER_*` и т.д.) или в `config.py`.

## Правила для Claude Code

1. **Приоритет social velocity.** Любая доработка сигнала сначала улучшает
   `social.py` / вес social. Сырые счётчики упоминаний бесполезны — важна
   *скорость и ускорение*, а также *широта авторов* (не один спамер).
2. **Тайминг важнее громкости.** Не предлагай имена, которые уже сделали
   движение — это противоречит «до momentum-квантов». `early_stage` гейт священен.
3. **Мягкая деградация.** Новый источник данных не должен ронять пайплайн:
   при отсутствии ключа/ошибке — возвращай None и логируй, не бросай исключение.
4. **Секреты только через `.env`.** Никогда не хардкодь и не коммить ключи.
   `.env` в `.gitignore`. Токен в `bot.py` берётся из `config.py`.
5. **Это не инвестсовет.** Сигнал вероятностный, горизонт короткий = риск высокий.
   Каждый отчёт содержит дисклеймер — не удаляй его.
6. **Правь конфиг, а не логику.** Пороги/веса/эндпоинты живут в `config.py` и
   адаптерах, чтобы миссию можно было тюнить без переписывания скоринга.

## Запуск / проверка

```bash
pip install -r requirements.txt
cp .env.example .env          # впиши ключи
python -m scanner.pipeline    # сухой прогон скана в терминал
python bot.py                 # запустить Telegram-бота
```

## Идеи для развития (в русле миссии)

- Бэктест: логировать топ-N и мерить фактический +% за 1–3 дня → калибровать веса.
- Sentiment-фильтр упоминаний (bullish/bearish), а не только объём.
- Детект «первой искры»: аномалия velocity на фоне тишины по цене.
- Дедуп ботов/спама в social, взвешивание по репутации автора.
